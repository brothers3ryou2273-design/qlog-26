## HTTP／HTTPS接続の調査

2026-10-15、同じ環境・同じホストに対して比較しました。

| 確認項目                                                   | 結果                                                                |
| ---------------------------------------------------------- | ------------------------------------------------------------------- |
| `http://wiki.mhxg.org/`                                    | HTTP 200。HTTPSへのLocationヘッダーなし                             |
| 村★1〜3一覧と上記14個別ページ                              | HTTP 200、本文のクエスト名・条件を確認                              |
| `https://wiki.mhxg.org/`                                   | プロキシから503、`upstream ... connection timeout`                  |
| Chromium 154.0.8037.57の通常設定でHTTPトップを開く         | HTTP 200、HTTPのままトップページ表示                                |
| 変更後のアプリから「鬼面狩人を威す」の攻略リンクをクリック | HTTP 200、新しいタブで該当クエストのタイトル表示。HTTPSへの遷移なし |

HTTP取得とブラウザのナビゲーション記録にHTTPSへの強制変更はなく、アプリにも `upgrade-insecure-requests` 等の設定はありません。観測したHTTPS失敗はプロキシの上流接続タイムアウトであり、HTTPリダイレクトが原因ではありません。接続先の443番ポートやネットワーク経路のどちらが原因かまでは、この環境からは特定できません。

ブラウザ確認はこの環境のChromiumでの実測です。未マージのGitHub Pages公開サイトや、各利用者のブラウザのHTTPS専用モードでの動作は未検証です。HTTPは埋め込み画像・API取得ではなく、`target="_blank" rel="noopener noreferrer"` の外部ナビゲーションとして使用します。アプリ自体の配信や他サイトのURLはHTTPSのままです。

最初のcurl取得では本文がgzip圧縮されていたため、以降は `curl --compressed` で展開して確認しました。HTTPSのTLS検証を無効にする回避策は使用していません。
