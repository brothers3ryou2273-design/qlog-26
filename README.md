# QLOG / MHXX クエスト手帳

MHXX向けの、日本語・スマートフォン優先の静的クエストチェッカーです。React + TypeScript + Vite で構成し、GitHub Pages のリポジトリ配下に配置できます。

**村370件・集会所339件・G級230件・特殊許可228件・イベント144件・闘技大会17件・チャレンジ20件、計1348件を収録しています。** 特殊許可は従来12種が各16件、MHXX追加6種が各6件。通常LV・G段階・超特殊の正式名称、分類、実在する個別URLの集合を攻略レシピのHTTP一覧・個別ページと照合しました。

出現前提は攻略レシピを通常の基準資料とし、空欄は専門Wiki・必要な補助資料で補完します。通常のNPC会話・依頼受注・報告は補足表示し、クリア記録と入力HRから「記録上の前提達成」を判定します。実際の受注・受領状態とは区別し、対象不明の条件・未収録クエスト・納品済み状態・ランダム出現等は個別に明示します。

種別フィルターの「解放あり」で、監査済みの解放表示があるクエストだけに絞り込めます。名称検索・プレイ種別・未クリアのみと併用でき、表示設定も保存します。

一覧のタグ付近に小さな「解放あり」を表示します。装備・食材・狩技・施設等の存在を確認したクエストが対象で、具体名は詳細で確認できます。後続クエスト・HR進行だけでは表示しません。

一覧の収録と、条件・解放要素の完全確認は分けています。村上位に食材・施設の具体名が不明な7件があり、PR #4までの未確認事項も保持しています。内部の確認状態と出典は維持し、通常一覧には「一部確認」バッジを表示しません。集会所下位の緊急3件にも施設印の対応不明点を残しています。全体は [データ確認記録](docs/DATA.md)、第8段階のG級収録・既存前提7件の変更と未確認事項は [G級の監査](docs/G_RANK_AUDIT.md)、一覧表示の分類は [解放表示監査](docs/unlock-indicators-audit.json)、前回の上位・HR・進行調査は [集会所上位の監査](docs/UPPER_HUB_AUDIT.md)、前回の下位監査は [集会所下位の監査](docs/HUB_AUDIT.md)、上位の採用根拠・不一致・未確認事項は [村上位の監査記録](docs/UPPER_VILLAGE_AUDIT.md)、前回の施設13件の再調査は [施設の確認記録](docs/FACILITY_AUDIT.md) を参照してください。

特殊許可は「二つ名」欄で18種から選び、各グループの段階順・クリア数を表示します。チェックは**自分で受注・クリアし、ゲーム内の段階が進んだ状態**の記録です。参加クリアの別記録や、特殊許可券の所持・消費の管理は行いません。

特殊許可の収録数・解放116項目・出典の相違・残る調査・テスト結果は [第9段階監査](docs/PERMIT_AUDIT.md) を参照してください。既存の監査ファイルは保全しており、`docs/DATA.md`等は第8段階までの記録です。解放分類の新規分は [特殊許可の分類監査](docs/permit-unlock-indicators-audit.json) に分離しています。

闘技大会とチャレンジは別カテゴリの「全ランク」一覧で利用できます。**第11段階は部分完了**です。攻略レシピ掲載の17件（ハンター11／ニャンター6）と20件（ハンター14／ニャンター6）を取得・登録しましたが、専門Wikiの追加チャレンジ6候補や全件範囲の照合が残っています。17件／20件を日本版MHXXの確定総数とは扱いません。

ニャンター12件のサポート傾向・評価時間は出典表記で表示し、確認できた出現条件5件を既存G級IDへ接続しました。従来闘技大会10件の前提、ハンター25件の武器・評価時間、難易度区分等は未確認です。記録するのはクリア有無だけで、A/S評価・自己ベスト・武器・ソロ／ペアは保存しません。横断達成報酬をクリアチェックだけで自動取得判定せず、単独報酬へ複製しません。調査結果と制限は [闘技大会監査](docs/ARENA_AUDIT.md)・[チャレンジ監査](docs/CHALLENGE_AUDIT.md) に記録しています。旧1311件と過去の監査は変更していません。

## 開発

Node.js 24（推奨、CI・動作確認済み）または22.12以上の22系、npmが必要です。

```sh
npm ci
npm run dev
```

```sh
npm test                  # 条件式、データ整合性、保存・復元の単体テスト
npm run build             # TypeScriptの検査と本番ビルド
npx playwright install --with-deps chromium
npm run test:e2e           # PC幅・スマホ幅で本番ビルドをブラウザ検証
```

ブラウザテスト前に必ずビルドしてください。E2Eは静的な `dist` を起動します。既存のChromiumを使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e` とします。

GitHub Pagesと同じサブパスの検証:

```sh
npm run build -- --base=/qlog-26/
npm run test:e2e
```

`npm run preview` でビルド結果をローカル確認できます。ビルド時の `base` は標準で相対パス `./` なので、ユーザーサイト、カスタムドメイン、リポジトリ配下の配置に対応します。アプリ内の画面遷移にサーバー側のルーティングは不要です。

## 保存とバックアップ

進捗は利用者のブラウザの `localStorage` に保存します。サーバーには送信しません。1ブラウザ・オリジンにつき1キャラクターです。ブラウザのデータ削除、プライベートモード、別端末への移動に備え、定期的に「JSONを書き出す」を実行してください。

「JSONから復元」でファイルを選び、確認画面で「追加して復元」します。既存のクリア記録とファイルの記録の和集合になり、現在のHRは維持します。「現在の進捗をファイルで置き換える」を選んだ場合はクリア記録とHRをファイルの内容で置き換えます。確認・キャンセルの段階では進捗は変更されません。現データにないIDも保存・再出力され、将来のデータ追加で再び表示できます。

```json
{
  "schemaVersion": 1,
  "dataset": "mhxx",
  "completedQuestIds": [],
  "hr": 3
}
```

`hr` は省略可能です。過去の `dataset` のない形式は実データとして扱います。架空データは `dataset: "demo"` と別の保存キーを用い、実データには読み込めません。

保存キーは実データ `qlog.mhxx.progress.v1`、架空データ `qlog.mhxx.demo.v1`、表示設定 `qlog.mhxx.view.v1` です。壊れた既存データを検出すると進捗変更を止めます。「元の保存データを退避」で原文を保存し、内容を修復するか、必要な進捗をバックアップしてからブラウザのサイトデータを整理してください。修復前の自動リセットは行いません。

`localStorage` はオリジン単位です。同じGitHub Pagesホストの別アプリと併用する場合は保存キーを変更してください。公開オリジンを変更すると従来の進捗には直接アクセスできなくなるため、JSONで移行します。

## データ追加と出典管理

実データは `src/data/village-1.json`〜`village-10.json`、`src/data/hub-1.json`〜`hub-7.json`、`src/data/g-rank-1.json`〜`g-rank-4.json`、二つ名別の `src/data/permit-{slug}.json`（`src/data/quests.ts` で結合）、型は `src/lib/types.ts`、架空データは `src/data/demo.ts` に分離しています。既存の村★1〜10の照合記録を基に、追加のランクや未確認事項を個々の出典で確認してください。対象ランクの一覧・個別ページを確認し、取得失敗時は再試行を抑えて確認済み情報だけを反映します。

1. 実機で直接確認された情報を最優先し、通常は [MHXX攻略レシピ](http://wiki.mhxg.org/) を基準にする。欠落情報はMHXX専門攻略Wiki、次にGame8等の企業系Wikiで補完・比較する。多数決で採用しない。下位出典との不一致だけで、明確な攻略レシピの条件を未確認にしない。実機で確認したと主張する場合は実際の観測記録を残す。
2. 確認したクエストの固定ID（例: `village-1-recipe-元サイト識別子`）を付与する。名称や表示順をIDにしない。追加後のID変更・使い回しは禁止。同名でも別クエストには別IDを付ける。
3. `sources` に実際に確認したURL、リンク種別 `detail` / `list` / `home`、確認日 `checkedAt` を記録する。詳細URLは推測生成しない。URL検証は原則HTTPSとし、攻略レシピのみ `http://wiki.mhxg.org/` の標準ポートを例外とする。サブドメイン・別ポート・認証情報付きURLは許可しない。個別ページが未確認なら、実在確認できたトップ／一覧へのリンクと明記する。
4. 条件は `all` / `any` を明確に分ける。前提クエストは `quest_cleared` で固定IDを参照し、参照先も収録する。HRは `hr_at_least`、通常のNPC会話・受注・報告は `npcNotes`。貢献度・納品済み・未収録のイベント等の保存記録から判定できない条件は `external_flag`、対象不明・未収録の前提は `unknown`。確認済みで条件がないときのみ `none`。空のAND／ORは使用しない。
5. 検証状況は `verified` / `partial` / `unverified` と理由 `verificationNote` を設定する。未知の条件を含むデータは `verified` にしない。未確認情報を推測で補わない。解放要素の名称も確認できたものだけ `unlocks` に登録する。
6. `other` の解放を追加・変更する場合は `src/data/unlock-indicators.json` と該当段階の監査を更新する。第9段階では旧監査を保全し、`docs/permit-unlock-indicators-audit.json`を新設して旧監査と結合検証する。後続／進行は除外し、具体名不明の存在確認には出典の印の証拠を記録する。警告や未調査という状態だけから表示対象にしない。
7. `npm test` でID重複、参照欠落、循環依存、URL形式、空条件等を検査する。NPC補足・不明点の表示とバックアップ互換性をブラウザで確認する。
8. ランク別総件数と網羅性を元サイトで監査するまで、データ整備中の表示を維持する。村★1〜10の一覧集合は `docs/data-audit.json`、集会所★1〜3は `docs/hub-audit.json`、★4〜7は `docs/upper-hub-audit.json`、G★1〜4は `docs/g-rank-audit.json`、特殊許可は `docs/permit-roster-audit.json` と照合済みですが、全MHXXの未収録件数・全体総数は現在不明です。

補完候補は [MHXX攻略Wiki](https://mhx-wiki.com/)、[Game8 MHXX](https://game8.jp/mh-xx)。出典本文・報酬・詳細攻略の大量転載はしません。

## GitHub Pages公開

1. 変更をレビューして `main` にマージする。
2. GitHubの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定する。
3. `.github/workflows/deploy.yml` がビルド成果物 `dist` を公式Pagesアクションでデプロイする。必要ならActionsの **Deploy GitHub Pages → Run workflow** を実行する。
4. デプロイ後のサイトで、資産の読み込み、チェックと再読み込み、JSON復元、外部リンクを確認する。Pagesの公開範囲はGitHubのプラン・設定に従う。

`index.html` に `<meta name="robots" content="noindex, nofollow">` を設定しています。これは検索エンジンへの指示であり、認証・アクセス制限ではありません。クローラーが指示を取得できるよう、`robots.txt` でクロールを一律禁止する設定は追加していません。

CIは単体テスト、本番ビルド、PC幅とスマホ幅のE2Eを実行します。デプロイも単体テストとビルドの成功を条件にします。
