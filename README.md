# QLOG / MHXX クエスト手帳

MHXX向けの、日本語・スマートフォン優先の静的クエストチェッカーです。React + TypeScript + Vite で構成し、GitHub Pages のリポジトリ配下に配置できます。

**村★1〜6の一覧197件を収録しています（7・37・45・35・28・45件）。** 攻略レシピの各ランク一覧と実在する個別ページで、名称・ランク・分類・前提関係・確認できた解放要素を記録しています。攻略リンクはHTTPです。村★4〜6の108件を追加し、既存89件の固定IDを維持しています。

出現前提は攻略レシピを通常の基準資料とし、通常のNPC会話・依頼報告は詳細の補足に表示します。クリア記録・入力HRによる「記録上の前提達成」は、ゲーム内の受注可能状態とは区別しています。内部の確認状況は維持し、一覧の「一部確認」バッジは表示しません。

一覧の収録と、条件・解放要素の完全確認は分けています。曖昧な前提、範囲外の前提、施設の具体名・数値などが未確定な6クエストなどは個別に明示しています。村★7以上・他カテゴリは未収録です。内訳・採用根拠・出典・未確認点は [データ確認記録](docs/DATA.md) を参照してください。13件の施設再調査では食事・オトモ・荷車の10項目を補完しました。7件解決、3件は雇用枠の数値不一致、3件は施設内容未確認です。各件の解決状況・調査制限は [施設の再調査記録](docs/FACILITY_AUDIT.md) に記載しています。

「架空データで操作を試す」では、村★1〜3に各2件、合計6件の架空の動作例で、同名クエスト・OR・HR条件も試せます。実ゲームの情報ではありません。実データとは保存領域・バックアップを分離しています。

本ツールは非公式の個人制作物です。作者にサポート、修正、更新、データ網羅、問い合わせ対応の義務はありません。ゲーム内の情報を優先してください。カプコンおよび攻略サイトとは関係ありません。

## 開発

Node.js 24（推奨、CI・動作確認済み）または22.12以上の22系、npmが必要です。

```sh
npm ci
npm run dev
```

```sh
npm test                  # 条件式、データ整合性、保存・復元の単体テスト
npm run build             # TypeScriptの検査と本番ビルド
npx playwright install --with-deps chromium
npm run test:e2e           # PC幅・スマホ幅で本番ビルドをブラウザ検証
```

ブラウザテスト前に必ずビルドしてください。E2Eは静的な `dist` を起動します。既存のChromiumを使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e` とします。

GitHub Pagesと同じサブパスの検証:

```sh
npm run build -- --base=/qlog-26/
npm run test:e2e
```

`npm run preview` でビルド結果をローカル確認できます。ビルド時の `base` は標準で相対パス `./` なので、ユーザーサイト、カスタムドメイン、リポジトリ配下の配置に対応します。アプリ内の画面遷移にサーバー側のルーティングは不要です。

## 実装済み

- カテゴリ・ランク切り替え、名前検索、キー／緊急／依頼／通常、ハンター／ニャンター、未クリアの絞り込み
- 安定IDに基づくクリアチェックの即時保存、ランクごとの完了数・収録済み件数・進捗バー
- 表示設定の保存。同名クエストはIDで区別
- 詳細の展開、前提クエストへの移動、条件式から生成する逆引き
- AND／OR、前提なし、クエストクリア、HR、貢献度・納品済み等の外部条件、未確認条件。通常のNPC会話・報告は補足に分離
- 「記録上の前提達成／未達成／要確認」の3値評価。HR未入力・本当に不明な前提・未収録の前提は要確認。出現・受領・食材取得等を保証しない表示
- 解放要素の表示、参照リンクの種別（詳細／一覧／トップ）表示
- JSONバックアップのダウンロードと、件数・未収録ID・削除対象件数・HRの確認後の復元。標準は追加、明示的に選択した場合のみ置き換え
- 未知のIDの保持、不正なJSON・未対応形式・不正HR・2MB超の拒否、保存失敗の表示、壊れた既存保存内容の保護・退避
- カテゴリ別の収録・検証状況、未収録表示。イベント等を村の進捗に混算しない
- `noindex, nofollow`、GitHub ActionsによるテストとPagesデプロイ

## 保存とバックアップ

進捗は利用者のブラウザの `localStorage` に保存します。サーバーには送信しません。1ブラウザ・オリジンにつき1キャラクターです。ブラウザのデータ削除、プライベートモード、別端末への移動に備え、定期的に「JSONを書き出す」を実行してください。

「JSONから復元」でファイルを選び、確認画面で「追加して復元」します。既存のクリア記録とファイルの記録の和集合になり、現在のHRは維持します。「現在の進捗をファイルで置き換える」を選んだ場合はクリア記録とHRをファイルの内容で置き換えます。確認・キャンセルの段階では進捗は変更されません。現データにないIDも保存・再出力され、将来のデータ追加で再び表示できます。

```json
{
  "schemaVersion": 1,
  "dataset": "mhxx",
  "completedQuestIds": [],
  "hr": 3
}
```

`hr` は省略可能です。過去の `dataset` のない形式は実データとして扱います。架空データは `dataset: "demo"` と別の保存キーを用い、実データには読み込めません。

保存キーは実データ `qlog.mhxx.progress.v1`、架空データ `qlog.mhxx.demo.v1`、表示設定 `qlog.mhxx.view.v1` です。壊れた既存データを検出すると進捗変更を止めます。「元の保存データを退避」で原文を保存し、内容を修復するか、必要な進捗をバックアップしてからブラウザのサイトデータを整理してください。修復前の自動リセットは行いません。

`localStorage` はオリジン単位です。同じGitHub Pagesホストの別アプリと併用する場合は保存キーを変更してください。公開オリジンを変更すると従来の進捗には直接アクセスできなくなるため、JSONで移行します。

## データ追加と出典管理

実データは `src/data/village-1.json`〜`village-6.json`（`src/data/quests.ts` で結合）、型は `src/lib/types.ts`、架空データは `src/data/demo.ts` に分離しています。既存の村★1〜6の照合記録を基に、追加のランクや未確認事項を個々の出典で確認してください。対象ランクの一覧・個別ページを確認し、取得失敗時は再試行を抑えて確認済み情報だけを反映します。

1. 実機で直接確認された情報を最優先し、通常は [MHXX攻略レシピ](http://wiki.mhxg.org/) を基準にする。欠落情報はMHXX専門攻略Wiki、次にGame8等の企業系Wikiで補完・比較する。多数決で採用しない。下位出典との不一致だけで、明確な攻略レシピの条件を未確認にしない。実機で確認したと主張する場合は実際の観測記録を残す。
2. 確認したクエストの固定ID（例: `village-1-recipe-元サイト識別子`）を付与する。名称や表示順をIDにしない。追加後のID変更・使い回しは禁止。同名でも別クエストには別IDを付ける。
3. `sources` に実際に確認したURL、リンク種別 `detail` / `list` / `home`、確認日 `checkedAt` を記録する。詳細URLは推測生成しない。URL検証は原則HTTPSとし、攻略レシピのみ `http://wiki.mhxg.org/` の標準ポートを例外とする。サブドメイン・別ポート・認証情報付きURLは許可しない。個別ページが未確認なら、実在確認できたトップ／一覧へのリンクと明記する。
4. 条件は `all` / `any` を明確に分ける。前提クエストは `quest_cleared` で固定IDを参照し、参照先も収録する。HRは `hr_at_least`、通常のNPC会話・受注・報告は `npcNotes`。貢献度・納品済み・未収録の集会所クエスト等の保存記録から判定できない条件は `external_flag`、対象不明・未収録の前提は `unknown`。確認済みで条件がないときのみ `none`。空のAND／ORは使用しない。
5. 検証状況は `verified` / `partial` / `unverified` と理由 `verificationNote` を設定する。未知の条件を含むデータは `verified` にしない。未確認情報を推測で補わない。解放要素の名称も確認できたものだけ `unlocks` に登録する。
6. `npm test` でID重複、参照欠落、循環依存、URL形式、空条件等を検査する。NPC補足・不明点の表示とバックアップ互換性をブラウザで確認する。
7. ランク別総件数と網羅性を元サイトで監査するまで、データ整備中の表示を維持する。村★1〜6の一覧集合は `docs/data-audit.json` と照合済みですが、全MHXXの未収録件数・全体総数は現在不明です。

補完候補は [MHXX攻略Wiki](https://mhx-wiki.com/)、[Game8 MHXX](https://game8.jp/mh-xx)。出典本文・報酬・詳細攻略の大量転載はしません。

## GitHub Pages公開

1. 変更をレビューして `main` にマージする。
2. GitHubの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定する。
3. `.github/workflows/deploy.yml` がビルド成果物 `dist` を公式Pagesアクションでデプロイする。必要ならActionsの **Deploy GitHub Pages → Run workflow** を実行する。
4. デプロイ後のサイトで、資産の読み込み、チェックと再読み込み、JSON復元、外部リンクを確認する。Pagesの公開範囲はGitHubのプラン・設定に従う。

`index.html` に `<meta name="robots" content="noindex, nofollow">` を設定しています。これは検索エンジンへの指示であり、認証・アクセス制限ではありません。クローラーが指示を取得できるよう、`robots.txt` でクロールを一律禁止する設定は追加していません。

CIは単体テスト、本番ビルド、PC幅とスマホ幅のE2Eを実行します。デプロイも単体テストとビルドの成功を条件にします。
